运行状态

程序启动时会自动定位国内站和国外站的 CLI 并记住路径；路径失效了会自动重新遍历。 想强制重找、或者测一下站点连不连得上，用下面「站点」那一块里的按钮。

站点（国内站 / 国外站）

这台机器上可以同时装两个 WorkBuddy：国内站的配置目录是 ~/.workbuddy（端点 copilot.tencent.com）， 国外站是 ~/.workbuddy-ai（端点 www.workbuddy.ai）。两个站点各用各的登录账号和模型清单， 下面每一块都写清了「这个站点现在什么状态、登的谁的号、能拿出哪些模型」。
「测连通」会真的去连一次该站点的地址，告诉你通不通、不通卡在哪。

客户端接入地址

把下面的 Base URL 填到别的程序里（Cherry Studio / Chatbox / 脚本都行），模型名填 workbuddy-auto，点「测一下」会真的去拉一次模型列表验证通不通。

留空时不校验 —— 能连上这个端口的人都能用模型、也能改这里的设置。 如果服务是对外监听的（局域网/公网），留空等于门不锁，建议填一个长一点的随机串。 改完点保存立刻生效，当前页面会自动用上新密钥。
填了它就会出现在上面的地址表里，手机/外面就用这个。填域名时会自动把它加进反代域名白名单。
自动检测有时候会挑到 Clash / 虚拟网卡的地址，那把真实那块网卡的地址写在这里覆盖它。
用域名打开这个控制台时，浏览器发来的 Origin 是那个域名，必须在这里放行，否则「保存设置」会被 403 挡掉 （这是防止陌生网页偷偷改你权限的）。支持 https://*.example.com 子域通配；填 * 是全放，不建议。
放开工具权限 关闭时模型只能纯聊天。打开后它对所有调用方都能读写文件、执行命令 —— 等于把这台机器交出去，确认再开。两个站点一起生效。
流式输出逐字推 只影响流式请求（stream: true）：打开时模型每写几个字就往外推一次；关闭时等整段写完一次性发出去。 内容完全一样，关掉只是事件更少、老客户端兼容性更稳。改动对新建的会话生效 —— 已经在跑的会话要清空后才会按新设置重建。CLI 版本不支持逐字时会自动退回整条消息。
